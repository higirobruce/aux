03 · What's next

Recommended next move

One lane left

The plugin marathon and the whole warm-analog UI are done — the channel DSP suite, the seven floating plugin windows (incl. the Smart EQ panel), live signal-driven meters, and the reskin all merged to staging. The real Pitch corrector + plugin-delay- compensation (PR #12), its real-f0 graph + quality pass (PRs #15/#16), and the /design-system doc route (PR #14) are all merged too. That leaves a single big v0.3 lane: Clip editing v1 — cut / move / trim per stem on the timeline, now reachable on top of the read-only stem timeline.

Option A — Clip editing v1 (the lane)

Cut / move / trim per stem inside the timeline. Stays inside one stem — no inserts, no MIDI. Drag handles on each lane, snap, undo for edits.

Cost: Largest unlanded v0.3 lane. Edit-state in MixState (the clips field already exists), drag interactions on each lane, undo/redo stack, and host-side per-clip playback offsets in the audio engine.

Unblocked since: the read-only stem timeline shipped, so the editing surface exists.

Option B — Pitch shifter polish

The real-f0 graph (PR #15) and the quality pass (PR #16) are both merged: detection hardening, dry/wet blend, onset hold-off + note hysteresis, and a decimated YIN that lets several tracks run Pitch at once. What's left is the shifter core: the fixed two-tap overlap-add still colours a sustained corrected note (inherent to the method) — a comb-free shifter (true PSOLA with pitch marks) and a real formant stage are the remaining, larger DSP tasks.

Status: PR #15 + PR #16 merged; comb-free shifter + formants deferred.

Option C — Plugin-delay-compensation polish

PDC landed with the Pitch corrector (PR #12) for the main channel path; post-fader sends from a pitched channel aren't delay-matched yet, and the bypass↔engage transition could use a short crossfade.

Cost: Small, localized to the engine.

Option D — Engine taps for the meters

Two visualisers run on the mono peak level for want of an engine tap: a true L/R goniometer needs a stereo time-domain feed, and per-channel LUFS/true-peak readouts need their own meters.

Cost: Small-to-medium engine work; the windows already read whatever the host exposes.
